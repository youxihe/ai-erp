# AI ERP · 主数据对话新增/修改 Demo 验收清单（待开发）

**说明**：021A/021B 尚未实现，本文件是客户验收脚本。使用测试租户及随机唯一名称/编码，不要修改正式供应商与正式物料的敏感字段。

## 1. 供应商新增
企微：“帮我增加一家供应商【测试供应商-当日时分】，联系人张工，电话填演示号码（先由我提供）。”
- 预期：先查询重复，再展示“供应商｜名称/联系人/电话”；**未确认前 ERP 查不到新增**。
- 本人发送系统返回的准确 `确认建档{申请号}`：ERP 真正新增，返回 ID/名称；按新供应商可以生成采购草稿，库存不变。
- 负例：同名再新增时提示已有记录，不能出现 2 条；企微另外一人未经权限不得建档。

## 2. 供应商修改
企微：“把刚创建的测试供应商联系人改成李工。”
- 预期：展示“张工 → 李工”，旧手机/地址/税号/银行账号/余额不变；本人确认后查询 ERP 真值。重发确认不执行两次；无权限拒绝。

## 3. 客户新增及服务联动
企微：“新增客户【测试客户-当日时分】，联系人王工。”
- 预期：ERP `type=客户` 而不是供应商，返回真实 ID；只有获授权当前用户可见。将它作为 SERVICE 耗料客户时无需再手工进 ERP 后台选择。
- 若无需新客户，前台先给出已有同名客户候选，不制造重复。

## 4. 原料新增
企微：“增加原料【测试表面助剂】、编码【RM-TEST-当日时分】，单位 L；类别和规格从 ERP 已有选项选择。”
- 预期：绑定用户有权建档→显示真实字段摘要→本人确认→ERP 同时保存 Material + MaterialExtend 条码/SKU→可通过物料搜索找到。
- **任何仓库原料库存仍为 0**，确认建档不会入库；采购草稿可引用新编码。
- 同条码重复不再建档。

## 5. 原料修改
企微：“把 RM-TEST 的备注改为‘Demo 测试原料’。”
- 预期：只变备注；编码/基础单位/仓库初始库存、当前库存均不变。尝试“把这个原料库存改成100”需明确拒绝走主数据接口，引导独立采购/盘点流程。

## 6. 业务缺档续办（021C 上线后）
“采购新原料 X 10L，向新供应商 Y，入原料仓” → 先查两个档案是否存在 → 分别确认新增 → 返回**原采购业务**（10L/原料仓/指定供应商）并生成真实未审核草稿；用户不需重新报三次业务信息。最后必须再次发送采购**单独确认原文**才会改库存。
服务耗料新客户、MIX 新原料遵循相同原则。取消或过期不自动过账。

## 7. 安全/审计
- 不通过语言修改银行账户、税号、期初往来账、初始库存、SKU 基础单位或删除真实关联数据。
- 用户解绑/重新绑定后旧申请立即失效；跨租户/用户/企微 Bot 的申请号无法写入；群聊、模型自报确认无法写入。
- 同一申请的原始确认重复发不会第二次创建记录；冲突更新不覆盖对方变化。
- 测试记录：用户原始输入、字段摘要、真实ERP新增/更新前后数据、请求号及审计、权限拒绝、库存不变、最终业务续办状态。
