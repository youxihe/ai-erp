# AI ERP · 企微自然语言业务操作路线（2026-10-21）

## 产品目标与现状

用户无需学习 jshERP 菜单，即可在企业微信里自然语言查询业务、生成待审核草稿、确认后写入真实 ERP，再获得单号和库存变化。电脑仍使用 **Windows native** `F:\aierp-openclaw`、DeepSeek + WeCom WS；ERP jshERP Java 和已有 AIERP Gateway 为数据和业务权威。

**已验证**：AIERP-012A PR #19 已合并；1 个真实绑定账号企微库存查询成功；17/17 单合成身份测试 PASS；双账号仓库隔离 NOT_VERIFIED。**不能将聊天展示当作真实多用户安全验收**。

## 对话状态机（禁止业务模型直接审核）

- `INTENT_RECOGNIZED` → `COLLECTING`（槽位追问，仅缺什么问什么）→ `VALIDATING`（主数据/仓库/角色校验）→ `DRAFT_READY`（明确列出物料、单位、仓库、客户/供应商、金额、影响库存）。
- 只有可信的、**与原始消息/卡片事件绑定的用户确认**，才从 `DRAFT_READY` → `COMMITTING` → `POSTED`。仅靠模型的 `erp_draft_confirm({draftId})` 不构成用户确认。
- 订单草稿属于 `channel + botId + wecomUserId + ERP tenant + erpUserId + conversation + draftId`；保持幂等、有效期、确认数据版本与单次消费。任何回滚/重复调用返回已有结果，不再次扣库存。
- 没有可靠的企微卡片事件支持时，保底生成**一次性 H5 确认链接**并要求 ERP 身份验证，不对公网直接发布本机 Gateway；POC 可先使用同机 PC 登录界面确认。开放外网 H5 要另评估鉴权与网络方案。
- 群聊、跨账号、跨租户、用户/租户禁用、权限撤销、新绑定切换导致的确认，一律由服务端拒绝。

## 多模态返回：优先级与降级

1. 小结果（库存、单据状态、金额） → 企业微信短文本。
2. 小表格（<= 10 行） → Markdown，带中文字段名，默认隐藏无意义的 0 库存组合。
3. 大于 10 行/多页表格 → 服务端生成 **Excel 附件**，消息仅给摘要和操作提示。
4. 日期对比/趋势 → 服务端聚合数据、图表 PNG 附件；不让模型凭记忆计算金额。
5. 多筛选多维报表/草稿确认 → H5 受控页面；现阶段本机运行不可直接保证外部手机可打开，需按企微实际渠道能力和网络配置评估。
6. 企微官方模板卡片/附件能力必须通过真实消息收发试验，不假设所有卡片在个人/群聊/PC/手机端能力相同。

## 技术治理

- OpenClaw 只作意图识别、槽位追问、模型与 Tool 调用协调；**Java 适配器**是企业身份、签名、权限、数据过滤、幂等、审计和确认的唯一执行边界。
- **每个工具**具有只读/草稿/过账明确级别。禁止通用 SQL、shell、任意 HTTP、宿主机文件访问、共享 ERP 管理员会话。
- Model Tool 返回需结构化事实 + `details.summary`，并标注 `REAL_ERP` / error；不上传 Secret 或绑定码原文到 PR。
- 现有 `AierpGatewayController` 包含 `stock/query`、`purchase/draft`、`mix/draft`、`service/draft`、`draft/confirm`、`report/summary`；现有 Excel API 模板/预览/确认/回执都已存在，扩展 Agent **应复用而不是重写原生库存事务**。
