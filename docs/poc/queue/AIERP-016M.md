# AIERP-016M · 药水配制/组装生产：Excel/对话 → 草稿 → 本人确认 → 原生库存与回执

- **状态**：RELEASED / next_order #2（独立开发、不得与 017B2 同时部署 F:）；分支 `feat/aierp-016m-mix-sop` 从最新 master；避免同改 plugin/index.js，共用路由在最后一独立集成 PR 收口。
- **业务边界**：现有 jshERP `MIX` 是**组装/配制**，不是完整 MES/工单/BOM/多工序成本核算；允许用户明确指定配方，不能 AI 擅自推导真实化学比例。演示数据必须注明“测试配方，需用户确认”。
- **现有复用**：`AierpExcelService` 的 `MIX` 表（配制单号、成品编码、产出数量、原料编码、领用数量等），`AierpGatewayService.createDraftAs(...,'MIX')/confirmAs`、原生组装单据与仓库权限、015B 可信消息确认、015C 回执媒体。
- **MIX 校验**：同一配制单号多行原料组合成**一张**草稿，单号内成品/产出数量/单位/目标仓库一致性。原料仓消耗、成品仓产出数量在确认前为预计，确认后用**真实 ERP 单据及库存实际结果**展示。现代码 MIX 默认为“原料仓→成品仓”，Demo 文案必须明确；多仓/版本后续再设计。数量必须正且库存足够、物料/单位/仓库受控，原料不足则只报差额，不过账。
- **SOP**：`deploy/openclaw/plugins/aierp-erp-tools/sop/mix-prepare.mjs` 独立模块，可信企微工具只暴露准备未审核草稿、读状态，不提供模型直接审核；服务端受控 `prepareVerifiedMix` 从 Excel payload_json 取真数据并验证 sender/bot/binding/actor/tenant/warehouse/revision，或按用户明确授权的配方对话槽位构造草稿。
- **本人确认**：单张配制使用明确 `确认配制{数字draftId}` 的可信原始私聊（不是 LLM）；后端根据数据库草稿真实 bizType 决定原生 MIX 流程并审计，防跨类型混淆，重复确认返回同一单据且库存只变化一次。
- **回执**：清楚列出成品 FG-101 +实际产出，RM-A001/B002/C003 等原料各自扣减数量（实际按文件），原料仓/成品仓前后库存，配制原生已审核单号，PDF（若已支持对应 MIX 类型；不许用采购 PDF 冒充）。
- **测试**：1 张配制单 3 行不同原料，成品 FG-101 产出 1–2 L，**配比必须用用户确认的测试值**；准备阶段两仓库存均不变，用户真实确认后成品仓 +产出、各原料仓 −耗用；库存不足/配方重复/错误单位/仓库撤权/重放消息失败或幂等。禁止自行确认用户旧采购 #119。
- **注意**：源码 `MIX_HEADERS` 包含**两个“单位”列**，`unitAt` 必须以正确列位置读取，不能把成品与原料单位串起来。该场景不支持模型替客户确定实际化学配方。
- **交付**：代码/测试、脱敏库存快照、真企微草稿和仅用户本人触发的一次入库记录；Cursor Push READY_FOR_REVIEW，不能自 Merge，不可单独覆盖 F: 的已运行采购插件。
