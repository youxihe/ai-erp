# AI ERP · 企业微信业务消息展示规范（供 Cursor 直接落地）

适用：`@wecom/wecom-openclaw-plugin` 当前本机 Bot WS 私聊通道。已核实官方插件支持 Markdown、模板卡片和真实文件消息，但**当前安装版本和企微客户端最终渲染能力仍需逐一真实验收**。不要用原生 HTML/CSS 假装控制字体，也不接受用户聊天看到字面的 `<font>` 或 `MEDIA:`。目标是客户一眼能看懂核心单据。

## 渲染等级（优先级）
1. **官方模板卡片**：如果当前 Bot WS 能稳定发送，标题、摘要、强调金额、状态、真实下载文件卡片。客户端要能实际打开。不允许添加未经验证的点击审核操作。
2. **渠道 Markdown**：标题/加粗/状态、必要时三种内置字体色 `info`（成功/金额）、`warning`（异常）、`comment`（次要说明），**前提为本机 SDK 真实发送了 Markdown 类型并在 PC + 手机正确渲染**。
3. **纯文本降级**：使用短中文标题 + 必要换行，标记清晰，绝不能输出技术语法或颜色标签。

### 成功确认（已审核）
```text
✅ 采购入库完成
GW-PURCHASE-119 · 已审核

表面活性剂（RM-A001）  80 L
原料仓 · 华东化工
采购金额：¥1,600

入库前 170.7 L → 当前 250.7 L
回执：采购入库业务回执_GW-PURCHASE-119.pdf
```
仅返回来自真实 ERP 的原生编号/仓库/金额/库存（单位标准化，数字 2 位小数以内）；**实际附件发送成功前不能说“已发送”。**

### 待确认采购
```text
📝 采购单待确认
表面活性剂（RM-A001）  80 L
华东化工 · 原料仓
采购金额：¥1,600
回复「确认采购119」完成入库
```

### 用户索要 PDF（成功）
```text
📄 采购入库业务回执
GW-PURCHASE-119 · 已审核
采购金额 ¥1,600

〔此处附一条真正可点击下载的 PDF 文件消息〕
```
不出现 `MEDIA: F:\\...` 路径。

### 已审核但 PDF 发送失败
```text
采购单 GW-PURCHASE-119 已审核，入库不受影响。
PDF 暂未发送成功，请回复「重发回执」，或在 ERP 登录后下载。
```
仍保留服务端已审核回执，发送失败**不得重新发采购模板或重做采购事务**。

### 数据错误
```text
Excel 有 1 处需要修改：
第 4 行缺少采购单号。
请补上后重新发送文件。
```

## 技术协议与排版
- Java 返回**业务事实 DTO**，JS renderer 负责精确摘要和金额单位格式，不由 LLM 拼接十几段。
- Decimal -> `80 L`、`¥1,600`、`250.7 L`；别输出 `80.000000`、`{...json...}`、localhost、F: 私有路径。
- Markdown/卡片实际传 `msgtype` 与 payload；不要在纯 text 里写 Markdown/HTML，希望客户端猜。
- P0 仅做首屏一眼可读的“结果、物料、金额、仓库、下一步/附件”；最多 6-8 行。多行单据/列表显示前 3 行 + 合计 +安全入口，勿刷屏。
- Markdown 三色支持以**真实企微客户端**为准；未验证不能承诺任意字号、主题或背景色。
- 以 Screenshot/UAT 验收文件、文字层级、可点击 PDF、手机换行、企业微信宽度、用户通知噪音。

## 2026-10-24 渠道原生 card/chart/table 测试约束

实际 WeCom Bot WS 允许的消息类型以当前安装官方 SDK 及 PC/手机实际渲染为准。原生 template_card/markdown 若可用则用受控字段；不支持自定义 HTML/CSS 和任意表格/图表。复杂明细/统计统一后端生成 PNG 表格/柱折饼图并作为真实 image 消息发送，超长数据附 XLSX，正式入账还附对应 PDF 回执。所有展示从后端 BusinessResult DTO 而不是摘要字符串或首行正则解析。飞书未来使用独立 Feishu card renderer，不借用 WeCom 的协议。详细见 docs/poc/RICH_CHANNEL_RENDERING_AND_AUDIT_ARCHITECTURE.md。
