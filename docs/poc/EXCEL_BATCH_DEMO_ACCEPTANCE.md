# AI ERP · 企微 Excel 批量业务 Demo 主线验收

**用户当前要求**：不仅批量采购，还包括销售出库、生产/组装、客户服务耗料等。此文档代表 Demo 预期，非当前功能全部可用的声明。

## 一条标准演示（以批量采购为例）

用户：`我要批量采购，请发我 Excel 模板`
→ 机器人发送真正的可下载、可编辑的 `采购入库模板.xlsx`
→ 用户在 Excel 填三张单、十行物料，保存后**在企微原会话直接发送文件**
→ 官方 WeCom Plugin 将附件可靠接收并下载到受控临时位置；ERP 接收已可信绑定的文件和用户身份
→ AI 回复：
```text
批量采购文件已解析，共10行、3张采购业务单
可准备草稿：2张（8行）；有错误：1张（2行）
错误：第7行供应商不存在；第8行物料单位不一致
本次仅预览，库存与已审核单据未变化。
可以下载错误明细.xlsx 修改后重新上传，或确认仅处理2张有效草稿。
```
→ 用户明确选择有效业务单 → 后端生成带版本的未审核业务草稿
→ 真人企微私聊回复 `确认批次<BATCH-ID>` → 可信原始消息/挑战核验 → ERP 原生审核入库
→ 机器人返回已审核单号列表、成功/失败原因、各仓库存变化、`批次处理回执.xlsx`，必要时附 PDF；断线可查、重复确认不会再次过账。

## 场景优先级与业务含义

| Demo 场景 | 优先级 | 现有依据 | 必须补齐 |
|---|---|---|---|
| 采购入库 | P0 | XLSX 模板/预览/PC 实际过账 + 015B 企微单单可信确认 | 企微文件来回、批次 DRAFT、可信确认和回执 |
| 生产/药水配制 | P0 | XLSX `MIX` 组装配制模板/预览/原生网关 | 原料领用+成品产出，原生组装语义与多单批次 |
| 客户服务耗料出库 | P0 | XLSX `SERVICE` 模板/预览/原生其它出库网关 | 客户权限/批次草稿、受控原生出库 |
| 销售出库 | P0（差异实现） | XLSX `SALE` 仅模板；jshERP 有原生销售单据能力待审 | 明确销售出库 vs 服务耗料；受控接口和正式过账、测试 |
| 普通领料/其它出库 | P1 | 原生 ERP 能力待梳理 | 业务分类、专用安全规则、导入字段 |
| 调拨/退货/盘点/期初 | P2 | 期初目前只有模板 | 独立审批及差异处理，不随意放开 |

## 非功能/边界

- 预览绝不产生已审核单据与库存变化。Agent 不直接调用 `AierpExcelService.confirm`，该接口目前会执行原生过账。必须重新建立批次 DRAFT/可信确认流程。
- 用户可修订 Excel、可下载错误清单、可仅确认选择的合法单据。单据序号、用户/仓库权限、双企微绑定代际、批次哈希、单次确认、防重复入库必须实际验收。
- 文件接收与发送优先使用已有企微官方 Channel 的受控媒资能力，不直接启用全部 `wecom-cli` 或 shell/filesystem。用户手机在外网时不能发送打不开的 `localhost` H5 地址。
- 先演示采购的端到端，生产/服务再复用统一批次入口；不要把生产理解为完整 MES/BOM 成本核算。
- 维护本机 Windows native `F:\aierp-openclaw` 和已有 ERP Docker 测试数据，不重新安装。ERP 现存 2MB/200 行限制作为 POC 初期上限。所有新增过账测试必须是专用测试数据并经真实用户确认。
