# AIERP-015B · 采购入库业务回执 / PDF / 企微发送合同

> **业务回执** ≠ 增值税发票、收款凭证、对外运输签收单。只有真实 ERP 原生单据**已审核**、账面库存实际过账才允许生成“入库成功”回执。

## 一、用户交互

```text
用户：采购10升表面活性剂，供应商华东化工，原料仓。
助手：草稿106，表面活性剂 RM-A001，10 L，华东化工，
      参考金额 200 元，原料仓；待确认未入库。
      回复「确认采购106」提交，或「取消106」。

用户：确认采购106
助手：采购入库已完成 [真实原生编号]
      物料 表面活性剂 RM-A001；数量 10 L；供应商 华东化工；
      原料仓；实际库存 [before] → [after]；时间 [serverTime]；
      已生成《采购入库业务回执》。
      [在企微私聊中发送 PDF 附件；若渠道不支持则提供安全 ERP 下载入口]
```

如果恰好只有**一个**仍有效的待确认草稿，可允许“确认”，否则必须提示指明具体草稿，禁止由模型猜测。

## 二、服务器事实来源

| 字段 | 事实来源 | 规则 |
|---|---|---|
| 业务回执编号/receiptId | ERP 回执记录主键 | 同一原生账单稳定，幂等 |
| 原生单据编号、类型、审核状态 | `jsh_depot_head`（按租户与可见权限校验） | 必须状态已审核 |
| 单据时间、实际操作人、审核人 | 原生单据及审计记录 | 必须显示真实 actor，禁止固定为 admin |
| 供应商 | 原生单据关联且租户匹配的往来单位 | 与已过账单一致 |
| 仓库、物料中文名称/编码、数量单位、单价、金额 | 原生明细 + 当前可信主数据 | 单位不能混算，金额不自动推断含税 |
| 库存前后 | 在确认事务内由 ERP 记录的真实快照 | 无快照时仅展示“本次入库 +10 L”，**不得编造 before/after** |
| PDF生成时间、hash | ERP 内部生成与持久化 | SHA256 便于文件复核 |
| 文案 | 固定“采购入库业务回执” | 显著声明“此文件仅作业务记录，不作为税务发票或付款证明” |

推荐 PDF 文件名：`采购入库业务回执_GW-PURCHASE-<draftId>.pdf`（真实文件名不要携带敏感企业微信用户 ID）。

## 三、输出级别和发送状态

- `RECEIPT_TEXT_READY`：真实原生单据已审核，服务端构造简短中文回执；这是必选 P0。
- `PDF_GENERATED`：生成 A4 PDF，中文字体和打印边界经渲染检查；必须在 ERP 服务端而非模型中生成。
- `PDF_SENT_VERIFIED`：实际通过官方企微 Bot 渠道发送为文件消息，在用户的企微客户端收到并能打开 PDF；需真人实测。
- `PDF_DELIVERY_NOT_VERIFIED`：已生成 PDF，但不能证明企微消息收到/打开；提示登录 ERP 进行安全下载，**不要**将本机 `localhost` 作为外部手机可访问链接。
- `DELIVERY_FAILED_RETRYABLE`：不影响已完成 ERP 采购入库；安全重试文件发送，绝不重新过账。

文件发往**当初执行确认的可信企微身份**，且回执检索/下载时复查 ERP 租户、用户、仓库/单据权限与绑定 generation。禁止企微群聊分发、公开文件 URL、基于任意 draftId 返回他人 PDF。

## 四、技术落地

- 从确认事务提交后的真实 `CONFIRMED` 单据查询，渲染独立回执；不要在库存事务内长时间执行 PDF 编码、上传外部消息。
- 保存稳定 `receiptId + billNumber + tenantId + actorId + SHA256 + storageRef + generation`；PDF 文件存储可在 ERP 私有目录/文件服务，不放入 Git；断网或企微发送失败仍可用相同 `receiptId` 幂等重发。
- 现有 jshERP `pom.xml` 包含 iText 依赖，**使用之前审查其许可证**；可优先复用已有自有报表能力、HTML→PDF 或合规开源组件。中文字体须来自本机/系统合法来源，不把系统字体文件提交仓库。
- 企微发送 SDK / 官方插件的文件消息 API 由 Cursor 在当前安装版本中**实际验证**，不能用通用 shell/文件系统访问工具给 LLM 任意上传能力。文件由服务端/受控发送 adapter 推送，不暴露私有路径给模型。
- PDF 渲染后检查长供应商名称、多个物料行、金额小数、小单位、中文字体、分页；最少保存示例的截图/脱敏 PDF 测试证据（不提交真实客户隐私）。

## 五、验收门槛

单个专门测试采购 DRAFT 的真实链路：**企微用户确认消息 → 验证原始事件 → ERP 原生已审核单 → 库存+10 L → 回执文本真实 → PDF 文件生成与确认用户私聊送达**。确认重放只重新返回/发送相同回执，库存不再次变化。两个用户分别查对方回执时强制拒绝。

**优先保证文本回执和真实过账 P0，PDF 文件发送可单独标记待实测 P1；不要因为渠道文件限制而伪称整条业务已失败或重做过账。**
