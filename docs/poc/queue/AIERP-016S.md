# AIERP-016S · 客户服务耗料出库：Excel/对话 → 草稿 → 本人确认 → 原生出库回执

- **状态**：RELEASED / next_order #3（与 017B2/016M 可在独立分支开发，但**不能同时覆盖 F: 插件**）；分支 `feat/aierp-016s-service-outbound-sop` 基于最新 master；最终统一路由集成。
- **业务边界**：`SERVICE` 对应客户服务/耗料的原生其它出库业务，不等于标准销售发货、开票或收入确认。SOP 命名和单据回执必须明确“服务耗料出库”。
- **已有基础**：`AierpExcelService` SERVICE 表：服务单号、服务日期、客户名称、服务项目、药水编码、药水名称、耗用数量、单位、出库仓库、备注；`AierpGatewayService.createDraftAs(...,'SERVICE')/confirmAs` 与原生单据/权限。
- **规范化逻辑**：选择 ERP **真实有权限的客户**、服务项目、物料如 FG-101、成品仓及数量（初次测试 1 L）；ERP 实时查询库存，正数/单位/仓库/客户校验。用户确认前只 DRAFT，不减库存，明确告知预计耗料；确认后成品仓真实扣减，若库存不足/无权限/客户不存在则拒绝。
- **SOP**：`sop/service-consume.mjs`，只负责参数收集/后端 prepare、读结果；可信企微原文 `确认耗料{数字draftId}` 经独立 channel hook 后调用 ERP 正式审核，模型不能自行审核。
- **回执**：真实原生单号、客户、服务项目、耗用物料与单位/实际出库数量、库存前后、创建人，中文标题《服务耗料出库回执》。PDF 若无真实对应模板需明确开发，不允许复用采购 PDF 改标题假造已实施能力。
- **测试**：先从实际 ERP 客户主数据选择一个客户（勿假造客户名），成品仓 FG-101 实时数量 N，上传一张 SERVICE Excel 后生成草稿→库存 N 不变；本人确认后 N−1 L、原料仓不动，原生单据可查；负例无权限/客户错误/大于库存/重复确认不再次出库；不得悄悄生成 SALES 出库/财务应收。
- **交付**：独立源码/无过账自动化/受控真正企微本人确认回归证据，READY_FOR_REVIEW；Cursor 不自 Merge、不覆盖共享 F: 运行插件。

## 新客户续办依赖
如服务耗料时需使用新的客户，021A 负责真实 ERP type=客户 的建档与当前用户可见权限；建档本身不扣库存。021C 后续对客户创建完成的服务请求继续准备 DRAFT，不能自动服务出库。
