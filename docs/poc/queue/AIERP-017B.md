# AIERP-017B · Excel 多场景批量待确认业务单（批量导入 P0）

- **状态**：PLANNED / after 017A file channel & preview review
- **产品目标**：ERP 用户上传 Excel 后**只生成逐单校验/预览和可追溯、未过账草稿**，AI 返回“X 张可提交、Y 张有问题”，支持用户修改 Excel 重新提交、选中有效单据，最终一键/一句话确认整批。
- **不能**把现有 `AierpExcelService.confirm` 直接暴露给模型：它内部循环 `postOne → createDraft → confirm`，会实际过账。重用模板、解析、主数据校验，**拆开预览/准备草稿与真实提交**。

## 批次与单据模型

- `batchId` 关联上传文件 hash/渠道消息/企业微信 sender + bot + ERP actor/tenant + binding_generation；`businessKey` 是单号幂等维度，多行同号聚合成一张原生草稿。仅当前本人可读、可取消、可再次预览。
- 有效状态：`UPLOADED → PREVIEWED → DRAFT_READY → AWAITING_CONFIRM → POSTING → POSTED / PARTIAL_SUCCESS / FAILED / CANCELLED / EXPIRED`。每张业务单都有自己的状态/错误/审核单号。默认有错误行时拒绝“全部确认”；需要明确选择有效单据，**不能静默跳过错误行**。
- 用户修改文件再次上传产生新 revision/hash，旧待确认挑战失效。重新上传相同文件、消息重试或重复指令必须关联已有批次/业务键，不再新建重复采购草稿。
- 每场景复用相同 ERP actor/权限/主数据/仓库授权/单据号与审计机制，不能让 LLM 持有通用 SQL / URL 及 confirm。
- XLSX 导入条件当前 2MB/200 行，可先不扩大；后端应限制解压大小、工作簿格式、同名单号、无效单位、缺少供应商/客户、负数及公式/注入内容。
- 失败返回可下载的**带行号/列名/失败原因/修改建议**的错误回执 XLSX，供用户修改再上传，而不是要求逐条聊天手动更正。

## 核心验收

- 一个 10 行采购文件、3 张业务单：包含有效及无效明细；企微显示分组和错误，没有任何库存过账，生成仅有效、用户选中的草稿。
- 配制（原料仓扣料/成品仓加库存）与服务耗料（按客户/仓库出库）至少能生成真实且未入账草稿，库存不变；销售出库的可用性必须通过真实 ERP 原生场景审查后标注实现/未实现。
- 越权仓库、另一个企微发送者、跨租户、同秒换绑、未绑定、过期/重复文件全部拒绝或准确幂等。
- 提交 PR、无过账单测、真实企微预览截图与脱敏文件；由 ChatGPT Review 再 Release 017C。
