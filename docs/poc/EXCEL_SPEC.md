# Excel 双向业务交互规格（POC v1）

## 目标场景

用户在 AI 聊天中：
1. “给我一份采购入库 Excel” → 下载含列名的空表；
2. “今天采购入库表面活性剂 80 升，帮我生成 Excel” → 下载已预填的可编辑表；
3. 发送填写的 Excel → Agent 识别表的业务类型、匹配客户/供应商/物料/仓库 → 解析为业务草稿；
4. 展示每行成功/警告/拒绝，以及库存变更预估 → **人工确认** → jshERP 单据及库存变更；
5. 返回单据编号、状态和可下载的导入回执。

## Excel 工作表（本次演示 7 张）

Excel 模板包已经在本次 ChatGPT 会话提供用户下载；**以下字段是 Cursor 不依赖聊天附件的权威契约**。Cursor 要在仓库内落地一份可生成 XLSX 的模板代码，空白模板和预填模板同结构。

- `01物料期初`：物料编码｜物料名称｜物料类别｜单位｜仓库｜期初库存｜安全库存｜参考成本单价(元)｜默认供应商｜库存估值(元)。
- `02采购入库`：业务单号｜业务日期｜供应商名称｜物料编码｜物料名称｜入库仓库｜入库数量｜单位｜单价(元)｜业务备注。
- `03药水配制`：配制单号｜日期｜成品编码｜成品名称｜产出数量｜单位｜原料编码｜原料名称｜领用数量｜单位｜备注。
- `04服务耗料`：服务单号｜服务日期｜客户名称｜服务项目｜药水编码｜药水名称｜耗用数量｜单位｜出库仓库｜备注。
- `05销售出库`：业务单号｜业务日期｜客户名称｜物料编码｜物料名称｜出库仓库｜销售数量｜单位｜售价(元)｜备注。
- `06解析回执示例`：场景｜业务单号｜解析状态｜说明 / 校验反馈｜处理建议。
- `使用说明`：操作步骤、导入安全边界、数据性质。

第一行标题、第二行说明、**第三行为字段名，第四行开始是数据**。Excel 日期 `yyyy-MM-dd`，数量按两位小数显示。物料/单号列强制文本以保留前导零。样例为**虚构数据**，配制比例仅用于软件测试，不提供实际化学工艺指导。

## 导入状态机

```text
UPLOADED → PARSED → VALIDATED → PREVIEWED → USER_CONFIRMED
                       ↘ REJECTED         ↓
                                 ERP_SUBMITTED → POSTED / ERP_FAILED
```

每个文件和每条业务记录返回 `rowNo, sourceSheet, originalValues, normalizedValues, errors[], warnings[], status`；
复合业务单（配制）按**配制单号分组**，不能把每一子件独立创建组装单。处理大小写/空格/列名别名，但不把未知物料、客户和供应商硬猜成已有记录。进度与异常结果可下载 Excel 回执。

## 关键护栏

- 不直接写 SQL；新建草稿不改库存；确认后调用 ERP 业务服务并保留审计轨迹；
- 服务端验证用户权限、租户和仓库、有效单位、正数数量、可用库存；
- 同一业务编号多次上传或确认要幂等；应支持拒绝重复或关联原单；
- 避免跨文件的部分过账：明确采用单业务单事务；若批量是部分成功，必须明确回传成功/失败及单据号；
- XLSX 解析不执行宏或公式，公式单元格不得直接作为可信业务输入，CSV/Excel 注入需防护；
- 上传大小、条数、类型限制，导出文件名和 Content-Disposition 做中文编码兼容；
- 对话让 AI 负责**选择模板/字段映射/解释异常**，价格、库存和单据状态由业务 API 提供。
